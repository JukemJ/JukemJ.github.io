    Triple-CAN vehicle gateway

    In build

    • Teensy 4.1
    • C++
    • PlatformIO
    • KiCad
    • J1939
    • DBC

    The central controller on a prototype hybrid-electric truck. It sits between three separate CAN networks and decides what each one hears.

    • Routes, filters, and translates traffic between three isolated buses that carry both J1939 and proprietary messages.
    • Commands a separate genset controller over CAN. Every command frame carries a counter that is checked for freshness, and a stale or missing frame is handled as a fault.
    • Keeps an OEM instrument cluster alive by emulating its keep-alive traffic. Next step: control individual warning lights using the OEM signal database.
    • Runs on a custom KiCad board with star grounding, ferrite filtering, and shielded twisted pair to hold up next to high-voltage power electronics.

    Hybrid-electric truck program

    In build

    • BMS integration
    • HV safety
    • Charge control
    • Thermal
    • Harness design

    Systems integration on a series-hybrid heavy truck prototype: battery, generator, charging, cooling, and the control logic that ties them together.

    • Charge control firmware: a PI loop on an IR-compensated cell-voltage target, backed by a three-stage protection ladder that first sheds load and then latches a fault.
    • High-voltage safety built on hardware fail-safe relay interlocks, an HVIL chain, and precharge sequencing. Every failure has to end in a safe state, not just a reasonable-looking value.
    • A refrigerant system with two branches that cools both the cab and the battery chiller, sized for 45 °C desert heat. The cab side is commissioned and blowing cold.
    • Battery management and onboard charger integration over CAN, a J1772 charge inlet, and wiring documented from the netlist up.

    The program is confidential, so I'm keeping specifics off this page. I'm glad to go deeper in conversation.
